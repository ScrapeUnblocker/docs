The **Telegram** plugin turns a public Telegram channel into structured JSON. Give it a channel - a username like `durov`, `@durov` or a `t.me` link - and it returns the channel (title, username, description, avatar, verified mark, subscriber count and the photo, video and link counters) and its posts, newest first: id, link, date, the text as plain text and as Telegram's HTML, views, author signature, edited flag, forwards and replies, media with their links, polls, link previews, reactions, inline buttons, and the links, hashtags and mentions in the text.

One call reads one page (about 20 posts) by default. `max_posts` pages back through the channel's history, up to 500 posts per call; `before`, `after` and `since` bound the range, `q` searches inside the channel and `post_id` (or a post link) returns one post. It works for public channels only: users, bots, groups and private channels have no public preview and return `404`. No Telegram account, bot token or API key is involved.

## Channel and posts

```
POST /social/telegram-channel
```

| Field | Required | Notes |
| --- | --- | --- |
| `channel` | yes | Public channel: username (`durov`), `@durov`, or a t.me link (`https://t.me/durov`, `https://t.me/s/durov`). A post link (`https://t.me/durov/400`) returns that one post. |
| `max_posts` | no | Posts to collect, newest first, `1`-`500`, paging back through the channel's history. Each page fetched is billed as one request. Omit it for one page of the newest posts, billed once. |
| `before` | no | Only posts with an id below this one. Pass the `nextBefore` of a previous response to continue where it stopped. |
| `after` | no | Stop at this post id: only posts with a higher id are returned. |
| `since` | no | Stop at this date: only posts published on or after it (`YYYY-MM-DD` or an ISO-8601 datetime, UTC when no offset is given). |
| `q` | no | Search inside the channel: only posts matching this text. |
| `post_id` | no | Return only this post (a post id of the channel). |
| `proxy_country` | no | Proxy country the request is sent from (ISO-2, e.g. `US`). Leave blank to let the API pick. |

| Field | Notes |
| --- | --- |
| `id` / `url` | The post id and its `t.me` link. |
| `date` | Publish time, ISO-8601 UTC. |
| `text` / `textHtml` | The post text as plain text and as Telegram's own HTML. |
| `views` / `viewsRaw` | View count as a number and as Telegram prints it. |
| `author` | The author signature, on channels that sign posts. |
| `edited` | `true` when the post was edited. |
| `forwardedFrom` / `replyTo` | The channel or user a post was forwarded from, and the post it replies to. |
| `media` | Photos, videos, animations, round videos, voice notes, audio, documents and stickers: `type`, CDN `url`, `thumbnail` and `duration`, or title and size for files. |
| `poll` / `linkPreview` | A poll with its options, and the preview card of a shared link. |
| `reactions` | Reactions with their counts. A custom-emoji reaction has its `customEmojiId`, plus the standard `emoji` and `image` Telegram falls back to when the page shows one. |
| `buttons` | Inline buttons under the post. |
| `links` / `hashtags` / `mentions` | Links, hashtags and @-mentions found in the text. |

A key with no value for a post is left out, so each post carries only what it has. Every answer carries `postsReturned`, `pagesFetched`, `hasMore` and `nextBefore`; `query` echoes the filters you set.

## What you can build

- **Channel monitoring** - poll channels for new posts and their view counts.
- **News and signal feeds** - collect posts from many channels into one searchable stream.
- **Media archives** - save photos, videos and documents with their dates and captions.
- **Engagement research** - compare views and reactions across posts and channels over time.
