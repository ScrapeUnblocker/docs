The **Naver Place** plugin returns place data from Naver Map, the local search most people in Korea use for restaurants, cafes, clinics and shops, as structured JSON. It has two methods:

- **Search** - a query in Korean or English, such as `강남 맛집` (restaurants in Gangnam) or `Gangnam cafe`, returns up to 50 places with name, category, road and lot addresses, phone, coordinates, visitor rating, visitor and blog review counts, opening status, popular menus, booking and Naver Pay flags and the Naver Map link.
- **Details** - a place id or Naver Map link returns the full place: opening hours per day, description, directions, conveniences, menus with prices, photos, homepage and links, nearby subway stations and review statistics, with its first 10 visitor reviews and first blog reviews.

Korean text comes back as is. Each call is one page and one billed unit.

## Search

```
POST /maps/naver-place
```

| Field | Required | Notes |
| --- | --- | --- |
| `mode` | - | Set to `search` by `naverPlaceSearch`. In a raw request it is the default when no `place` is given. |
| `query` | yes | What to search for, in Korean or English: a category, a place name or both, e.g. `강남 맛집`, `홍대 카페`, `부산 호텔` or `Gangnam cafe`. |
| `longitude` | no | Search centre longitude (with `latitude`), e.g. `127.0276`. Naver ranks places around the centre, and each result then carries its `distance` from it. |
| `latitude` | no | Search centre latitude (with `longitude`), e.g. `37.4979`. |
| `max_results` | no | How many places to return, `1`-`50`. Default `50`. Naver answers one page of up to 50 places per search; move the search centre to reach other places. |
| `proxy_country` | no | Proxy country the request is sent from (ISO-2, e.g. `KR`, `US`). Leave blank to let the API pick. |

| Field | Notes |
| --- | --- |
| `position` / `id` | Rank in Naver's results and the Naver place id. Pass `id` to [Details](#details). |
| `name` / `category` / `businessType` | Place name, Naver's category (e.g. `일식당`, Japanese restaurant) and its business type (e.g. `restaurant`). |
| `address` / `roadAddress` / `jibunAddress` / `area` | Full address, road-name address, lot (jibun) address and the district. |
| `phone` | Phone number as Naver lists it. |
| `latitude` / `longitude` / `distance` | Coordinates, and the distance from the search centre when you set one. |
| `rating` / `visitorReviewCount` / `blogReviewCount` | Visitor rating and the numbers of visitor and blog reviews. |
| `status` / `statusDescription` | Opening status and its note, in Korean (e.g. `영업 중`, open now). |
| `microReview` / `popularMenus` / `options` | Naver's one-line summary, popular menu items and options such as reservations or group seating. |
| `imageUrl` / `imageUrls` / `imageCount` | Main image, more images and the photo count. |
| `hasBooking` / `bookingUrl` / `hasNaverPay` | Naver booking and Naver Pay flags. |
| `hotelMinPrice` / `representativePrice` | Lowest price for stays, and the representative price for salons and similar businesses. |
| `url` | The place's Naver Map link. |

`searchCentre` echoes the centre you passed, and `totalResults` is how many places Naver matched.

## Details

```
POST /maps/naver-place
```

| Field | Required | Notes |
| --- | --- | --- |
| `mode` | - | Set to `details` by `naverPlaceDetails`. In a raw request it is implied when `place` is given. |
| `place` | yes | The place id (`2097258400`), a Naver Map link (`https://map.naver.com/p/entry/place/2097258400`) or a Naver Place link (`https://m.place.naver.com/restaurant/2097258400/home`). |
| `sort` | no | Visitor review order: `relevance` (default, Naver's own order) or `recent` (newest first). |
| `proxy_country` | no | Proxy country the request is sent from (ISO-2, e.g. `KR`, `US`). Leave blank to let the API pick. |

<CodeGroup>

```bash cURL
curl -X POST "https://api.scrapeunblocker.com/maps/naver-place?mode=details&place=2097258400&sort=recent" \
  -H "x-scrapeunblocker-key: YOUR_API_KEY"
```

| Field | Notes |
| --- | --- |
| `place.address` / `place.jibunAddress` / `place.phone` | Road-name and lot addresses and phone; `isVirtualPhone` marks a Naver forwarding number. |
| `place.businessHours` | Opening hours per day (`day`, `open`, `close`, `breaks`, `lastOrder`), plus regular and irregular closed days. |
| `place.description` / `place.directions` | The owner's description and directions. |
| `place.conveniences` / `place.facilities` / `place.paymentMethods` / `place.parking` | What the place offers and how you can pay. |
| `place.keywords` / `place.links` / `place.homepage` | Owner keywords, homepage and social links. |
| `place.menus` / `place.menuImages` | Menu items with `name`, `price`, `description` and image, and photos of the printed menu. |
| `place.photos` / `place.photoCount` | Photos and the total photo count. |
| `place.bookingUrl` / `place.subwayStations` | Naver booking link and nearby stations with line, exit and walking time. |
| `place.reviewStats` | `averageRating`, `totalCount`, `starDistribution`, review `themes`, `menuMentions` and `keywordVotes` (Naver's "what visitors liked" votes). |
| `reviews` | First 10 visitor reviews: `body`, `rating`, `createdDate`, `visitedAt`, `verifiedBy` (receipt or payment record), `keywords`, `situations`, `media`, `reactions`, the `author`'s stats and the `ownerReply`. |
| `reviewSort` | `relevance` or `recent`, as requested. |
| `blogReviews` / `blogReviewsTotal` | First blog and cafe posts about the place (`title`, `excerpt`, `date`, `thumbnailUrl`) and how many exist. |

## What you can build

- **Korean local business data** - build restaurant, cafe or clinic lists for a district with addresses, phones and coordinates.
- **Location intelligence** - set a search centre and map what is around a site, with each place's distance.
- **Menu and price research** - collect menus with prices across competing places.
- **Reputation monitoring** - track ratings, review statistics and the newest visitor reviews with `sort=recent`.
