The **Booking.com Reviews** plugin returns a Booking.com hotel's newest guest reviews as structured JSON. Give it a hotel page URL (or the short `<cc>/<slug>` form, such as `gb/the-savoy`) and it returns each review's date, score out of 10 with Booking's score word and a rating band, title, what the guest liked and disliked, the reviewer's name and country, trip and traveler type, nights, month of stay, helpful votes and language.

Booking serves the **newest 15 reviews written in each language**. Pick the languages with `languages` (18 to choose from, or `all` for up to 270 reviews), cap the total with `max_results` and drop older reviews with `since`. That makes it a fit for monitoring new reviews and multilingual sentiment, not for downloading a hotel's full review history. Each language read is one billed unit (`pagesFetched`).

Try it in the dashboard first: [app.scrapeunblocker.com/dashboard/plugins](https://app.scrapeunblocker.com/dashboard/plugins). You get a live results view plus a copy-paste snippet.

## Hotel reviews

```
POST /travel/booking-reviews
```

| Field | Required | Notes |
| --- | --- | --- |
| `hotel` | yes | Booking.com hotel page URL, e.g. `https://www.booking.com/hotel/fr/le-meurice.html` (a locale suffix such as `.en-gb.html` and query parameters are fine), or `<cc>/<slug>` such as `fr/le-meurice`. |
| `languages` | no | Review languages, comma-separated, or `all`: `en`, `de`, `fr`, `es`, `it`, `nl`, `pt`, `pl`, `ru`, `ja`, `zh`, `ko`, `sv`, `da`, `no`, `fi`, `cs`, `tr`. Default `en`. Read in the order given until `max_results` is reached; each language is one billed unit. |
| `max_results` | no | How many reviews to return across languages, `1`-`270` (at most 15 per language). Default `15`. |
| `since` | no | Only reviews written on or after this date (`YYYY-MM-DD`). |
| `proxy_country` | no | Proxy country the request is sent from (ISO-2, e.g. `US`, `DE`). |

### Review fields

| Field | Notes |
| --- | --- |
| `id` / `language` | Review id and the language it was written in. |
| `reviewDate` / `reviewDateText` | Review date (`YYYY-MM-DD`) and Booking's own date line, in the review's language. |
| `rating` / `ratingText` / `ratingBand` | Score out of 10, Booking's score word when shown (e.g. `Wonderful`), and a band from `exceptional` down to `very_poor`. |
| `title` / `positiveText` / `negativeText` | Review title and what the guest liked and disliked. Any of them can be `null`. |
| `reviewer` | Reviewer `name` (as Booking shows it), `country` and ISO `countryCode`. |
| `tripType` / `travelerType` | E.g. `leisure`; `solo`, `couple`, `family` and similar. |
| `nights` / `stayMonth` / `stayText` | Nights stayed, month of the stay (`YYYY-MM`) and Booking's stay line. |
| `helpfulVotes` / `submittedFromMobile` | Helpful votes and whether the review was written on a phone. |
| `tags` | Booking's raw review tags, in the review's language. |

The top-level `languages` array reports each language read: `status`, `reviewsFound`, and `capped: true` when Booking holds older reviews in that language than the 15 it serves. The response holds the reviews only - not the hotel's name or overall score; use the [Booking.com Hotels](/plugins/booking) plugin for those.

## What you can build

- **New-review monitoring** - poll a hotel daily with `since` and alert on low scores or new complaints in `negativeText`.
- **Multilingual sentiment** - read the newest reviews in every language with `languages=all` and compare what each market likes.
- **Competitive benchmarking** - track the latest scores and rating bands of competing hotels.
- **Guest-mix analysis** - break recent reviews down by `travelerType`, `tripType`, reviewer country and length of stay.
