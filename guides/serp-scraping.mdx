The `/serpApi` endpoint scrapes Google search results and returns normalized JSON. It handles the CAPTCHA gauntlet, ad rendering delays, and proxy rotation that make Google scraping painful.

## Minimum request

<CodeGroup>

```bash cURL
curl -X POST "https://api.scrapeunblocker.com/serpApi?keyword=best+running+shoes" \
  -H "x-scrapeunblocker-key: YOUR_API_KEY"
```

```python Python
import requests

r = requests.post(
    "https://api.scrapeunblocker.com/serpApi",
    params={"keyword": "best running shoes"},
    headers={"x-scrapeunblocker-key": "YOUR_API_KEY"},
    timeout=120,
)
data = r.json()
```

```javascript Node.js
const res = await fetch(
  "https://api.scrapeunblocker.com/serpApi?keyword=best%20running%20shoes",
  {
    method: "POST",
    headers: { "x-scrapeunblocker-key": "YOUR_API_KEY" },
  }
);
const data = await res.json();
```

</CodeGroup>

Every response carries `keyword`, `proxyCountry`, `totalResults`, the count
fields (`topAdsCount`, `bottomAdsCount`, `organicResultsCount`,
`resultsCollected`), `pagesFetched` (how many result pages were rendered - this
is how many API requests the call was billed, see [`pages_to_check`](#pages-to-check)),
the three result lists (`topAds`, `bottomAds`, `organic`), `aiOverview` and the
[other blocks of the page](#other-blocks-on-the-page). On a country fallback it also carries `requestedCountry` and
`note` (see [`proxy_country`](#proxy_country) below).

### Organic results and ads

| Field | Notes |
| --- | --- |
| `title`, `description`, `position` | As Google shows them. `description` is the snippet, without the date Google prints ahead of it; an empty string when Google shows none. `position` counts across pages. |
| `url` | The real page URL. Google hides it behind a redirect on the results page; we follow that redirect for you. If it cannot be followed in time, `url` is the site's home page. |
| `displayedUrl` | The breadcrumb Google prints under the title, e.g. `https://www.g2.com › ... › CRM Software Resources`. |
| `domain` | The site's hostname, without `www.`. For an ad, the domain the ad shows (an ad's `url` can be a click tracker). |
| `source` | Organic only: the site's name Google prints above the breadcrumb (`G2`). |
| `date` | Organic only: the date Google prints with the snippet (`Apr 1, 2025`, `3 days ago`), or `null`. |
| `advertiser` | Ads only: the advertiser's name. |
| `favicon` | The site icon Google shows next to the result or ad: an image URL, or a small inline `data:` image (up to 4 KB), else `null`. |
| `sitelinks` | The extra links under a result or an ad: `title`, `url`, `description` (`null` when Google shows none). Organic sitelink URLs are real page URLs, e.g. `{"title": "Ways to save", "url": "https://www.comparethemarket.com/car-insurance/#jump-6-ways-you-could-save-on-your-car-insurance"}`. An ad sitelink behind Google's ad click tracker has `url` `null` (following it would bill the advertiser); one behind a `/goto` redirect keeps Google's link. `[]` when there are none. |
| `rating` | Organic only: the star line, `{"value", "max", "reviews", "url"}` (`url` is `null`: Google's star line has no link), or `null`. |
| `richSnippet` | Organic only: the extra facts line under the snippet, e.g. `3.8 (4) · $8.00 · Business/Productivity`, or `null`. |
| `thumbnail` | Organic only: the result's own picture (an image URL or a small `data:` image), or `null`. |

Every organic result and ad carries these keys, `[]` or `null` when Google
shows nothing for them. The [Bing](/plugins/bing) endpoint returns the same
keys; DuckDuckGo, Yahoo and Brave return the keys up to `description`, so
switching engines only changes the path.

### `aiOverview`

Google's AI-written summary above the results, or `null` when the search does
not have one. Whether Google generates an overview depends on the query and the
region, so treat this as an extra rather than a guarantee - a commercial query
usually has none, an informational one usually does.

| Field | Notes |
| --- | --- |
| `text` | The overview as plain text, one paragraph, heading or list item per line. |
| `markdown` | The same overview as Markdown: headings, nested lists, and formulas written as LaTeX (`$...$`), ready to display or to pass to an LLM. |
| `sources` | The hostnames the overview cites, e.g. `energysage.com`. Google's own sites, such as YouTube, are left out. |
| `references` | The pages the overview cites: `title`, `url`, `source` (the site's name), `domain` and `snippet`. `url` is the real page URL, or `null` when Google exposes no address for that page. A cited URL that cannot be tied to one of the cards is listed on its own, with `title` and `snippet` `null`. |

## Other blocks on the page

The first results page also returns Google's other blocks. Each is an empty
list (`[]`) or `null` when the search has none - which blocks Google shows
depends on the query and the country.

| Field | What it holds |
| --- | --- |
| `peopleAlsoAsk` | The "People also ask" questions: `question`, `position`. Google loads an answer only when a question is opened, so there is none. |
| `relatedSearches` | The searches Google suggests below the results, as strings. |
| `relatedSearchLinks` | The same searches as `query` with the Google search `url` for it, in the same order. |
| `knowledgeGraph` | The knowledge panel of an entity search: `title`, `subtitle`, `description`, `source` (`name`, `url`) and `attributes`, the panel's labelled facts. |
| `topStories` | News cards: `title`, `url`, `source` (publisher), `date` as shown, `publishedAt` (ISO time), `position`. |
| `videos` | Video cards: `title`, `url`, `platform`, `channel`, `date`, `duration`, `position`. |
| `localResults` | The map pack: the same fields as [Google Local](/plugins/google-local) (`name`, `rating`, `reviews`, `category`, `address`, `phone`, `website`, `hours`, ...). |
| `shoppingResults` | Product cards: `title`, `price`, `priceRaw`, `currency`, `currencyCode`, `merchant`, `rating`, `reviewCount`, Google's product ids, `position`. |
| `spellingCorrection` | `type` (`showing_results_for`, `including_results_for` or `did_you_mean`) and `query` when Google corrected or questioned the query. |

A real knowledge panel, trimmed, for `keyword=barack obama`:


<Note>
  `topAds` and `bottomAds` cover the paid units wherever Google puts them,
  including the blocks it now renders inside the organic column. Anything paid is
  in one of those two lists and never in `organic`.
</Note>

## Useful parameters

### `pages_to_check`

How many SERP pages to scrape, 1 to 10. Defaults to 1.

```bash
curl -X POST "https://api.scrapeunblocker.com/serpApi?keyword=running+shoes&pages_to_check=3" \
  -H "x-scrapeunblocker-key: YOUR_API_KEY"
```

Results from all pages are concatenated into `topAds`, `bottomAds`, and `organic` with `position` reflecting cross-page ordering.

**Billing:** each result page rendered is charged as one API request - a `pages_to_check=3` call that returns three pages counts as 3 requests, not 1. The `pagesFetched` field in the response tells you exactly how many were charged (it can be lower than `pages_to_check` when Google has fewer pages). `/getPageSource` and `/getImage` bill a flat 1 per request; plugins that page through results count pages the same way as `/serpApi`, and each plugin page says how its calls are counted.

### `proxy_country`

Two-letter ISO code forcing the request through that country's IP pool. Affects what Google shows you - SERP composition varies by region.

```bash
curl -X POST "https://api.scrapeunblocker.com/serpApi?keyword=pizza&proxy_country=de" \
  -H "x-scrapeunblocker-key: YOUR_API_KEY"
```

**Available countries (ISO2):** `AT`, `AU`, `BE`, `BR`, `CA`, `CH`, `CN`, `CZ`,
`DE`, `DK`, `ES`, `FI`, `FR`, `GB`, `HK`, `HR`, `IE`, `IT`, `JP`, `KR`, `LT`,
`LU`, `NL`, `NO`, `NZ`, `PL`, `RO`, `SE`, `SG`, `TR`, `TW`, `US`. The list
follows our exits and can grow; a fallback's `note` (below) always carries the
current one.

**Without `proxy_country`** the exit is picked from the whole pool, so the
results can come from any of these countries and differ between calls. Set it
whenever the market matters.

**Country fallback.** If you request a country we do not have an exit for, the
request does **not** error. The results are served from an available exit, and
the JSON response carries two extra fields so you know it happened:

| Field | Type | Meaning |
| --- | --- | --- |
| `requestedCountry` | string | The ISO2 country you asked for. |
| `note` | string | Human-readable explanation of the fallback. |

```json
{
  "keyword": "pizza",
  "proxyCountry": "GB",
  "requestedCountry": "IL",
  "note": "Country 'IL' is not available. Results were served from 'GB'. Available countries: AT, AU, BE, BR, CA, CH, CN, CZ, DE, DK, ES, FI, FR, GB, HK, HR, IE, IT, JP, KR, LT, LU, NL, NO, NZ, PL, RO, SE, SG, TR, TW, US.",
  "organic": [ ... ]
}
```

<Note>
  `requestedCountry` and `note` appear **only** on a country fallback. On a
  normal request where your `proxy_country` is available, neither field is
  present and `proxyCountry` echoes the country you asked for.
</Note>

### `wait_after_load`

Extra seconds to wait before extraction, on top of the wait we already do.

You should not normally need it: extraction waits for the paid units to finish
arriving before reading the page, so ads are not missed because of timing. Reach
for this only when you have a specific reason to let a SERP settle longer - it
is added to your response time as-is.

```bash
curl -X POST "https://api.scrapeunblocker.com/serpApi?keyword=insurance&wait_after_load=3" \
  -H "x-scrapeunblocker-key: YOUR_API_KEY"
```

### `captcha_pause`

Kept for compatibility; it has no effect. A CAPTCHA is handled on our side by retrying from other exits, so leave it at 0. If a country keeps answering `403`, try another `proxy_country`.

## Errors

| Code | Meaning |
| --- | --- |
| `403` | Google CAPTCHA after retries on multiple proxies. Try a different `proxy_country` or wait. |
| `502` | Zero results with no "no results" notice on the page, on two separate fetches - an upstream block, not an empty search. Retry. |
| `504` | SERP fetch timed out. Lower `pages_to_check` or retry. |
| `422` | Missing `keyword` or invalid parameter range |

A keyword Google genuinely has no results for is **not** an error: you get `200`
with `resultsCollected: 0` and an empty `organic` array. This is normal for narrow
`site:` queries, and it means you can trust an empty result set instead of retrying it.

## Tips

- **Phrase keywords like a user would.** `keyword=best+pizza+nyc` performs differently from `keyword=best%20pizza%20nyc%202026`. Use spaces or `+`, not commas.
- **`totalResults` is Google's own figure, not a count.** It is the "About N results" number Google prints on the page, passed through as it is, and `null` when Google does not show one. Google's figure is often far from the size of its index (for many queries it now prints a few hundred), so do not read it as how many pages match. Count what you collected with `organicResultsCount`.
- **Cross-page dedup is your job.** If you call with `pages_to_check=10`, expect some overlap on borderline results. Dedup on `url`.
